# REST API (v1)

Base URL: `https://api.<domain>/api/v1`. The OpenAPI schema is generated by FastAPI at
`/api/v1/openapi.json`, with Swagger UI at `/api/docs` (disabled in production unless the
request comes from staff).

## Conventions

- JSON, snake_case. Money: `{"amount": 1299, "currency": "CAD"}` (minor units).
- Auth: `Authorization: Bearer <access_token>`; refresh via HttpOnly cookie.
- `Accept-Language` selects the language for server-rendered content (emails, PDFs).
- Lists: `?page=1&page_size=25` (max 100) → `{"items": [...], "page": 1, "page_size": 25, "total": 312}`.
- Errors:
  ```json
  {"error": {"code": "shipment.not_voidable", "message": "This label can no longer be voided.",
             "details": {}, "request_id": "01J…"}}
  ```
  HTTP status codes: 400 validation, 401 unauthenticated, 403 forbidden, 404 not found
  (also used for other accounts' resources), 409 state conflict, 422 schema validation,
  429 rate limited, 502 provider error.
- `Idempotency-Key` (UUID) **required** on endpoints marked 🔁. Replays with the same key and body
  return the original response; the same key with a different body → 409.
- Test data: resources include `"is_test": true` when created with sandbox/mock providers;
  rates include `"source": "easypost" | "mock"`.

Legend: 🌐 public · 👤 authenticated customer · 🛡 staff (permission listed) · 🔁 idempotent

## Auth
| Method | Path | | Description |
|---|---|---|---|
| POST | `/auth/register` | 🌐 | email, password, names, country, locale → sends verification email |
| POST | `/auth/verify-email` | 🌐 | `{token}` |
| POST | `/auth/resend-verification` | 🌐 | always 202 (no account enumeration) |
| POST | `/auth/login` | 🌐 | → `{access_token, expires_in}` + refresh cookie, or `{mfa_required: true, mfa_token}` |
| POST | `/auth/login/mfa` | 🌐 | `{mfa_token, code}` (TOTP or recovery code) |
| POST | `/auth/refresh` | cookie | rotates refresh token → new access token |
| POST | `/auth/logout` | cookie | revokes current session |
| POST | `/auth/logout-all` | 👤 | revokes all sessions |
| POST | `/auth/password/forgot` | 🌐 | always 202 |
| POST | `/auth/password/reset` | 🌐 | `{token, new_password}`; revokes sessions |
| POST | `/auth/password/change` | 👤 | `{current_password, new_password}` |
| POST | `/auth/mfa/setup` | 👤 | → otpauth URI + QR (SVG) |
| POST | `/auth/mfa/enable` | 👤 | `{code}` → recovery codes (shown once) |
| POST | `/auth/mfa/disable` | 👤 | `{password, code}` (not allowed for staff) |
| POST | `/auth/mfa/recovery-codes` | 👤 | `{code}` → new recovery codes |
| GET | `/auth/sessions` | 👤 | active sessions |
| DELETE | `/auth/sessions/{id}` | 👤 | revoke one |

| GET | `/shipments/{id}/tracking` | 👤 | full event timeline |
| GET | `/shipments/export` | 👤 | CSV, same filters as list |

> The master prompt's `POST /shipments/{id}/purchase` is replaced by the checkout endpoints below,
> which support one or many labels per payment (D-011) and the authorize→buy→capture flow (D-010).
